# HooksGraph Theme (`packages/theme/`)

WordPress classic-theme bootstrap shim around the [`@hooksgraph/viewer`](../viewer/) React app. All rendering logic lives in the viewer; this package is just enqueue + data-URL plumbing.

> User-facing install / build instructions live in [`README.md`](./README.md). This file documents the things an agent editing the theme needs to remember.

## Layout

```
style.css           Theme header (Theme Name, Version, …) + minimal global CSS for the
                    viewer mount (#root sizing, body background, fallback styles).
index.php           Fallback template — any route other than the front page lands here
                    with a "visit /" notice. Not the viewer.
front-page.php      Hardcoded classic template: DOCTYPE shell, wp_head(), wp_body_open(),
                    <div id="root">, wp_footer(). The viewer mounts on #root.
404.php             Standard 404 template.
functions.php       Theme bootstrap. Reads assets/manifest.json, enqueues built JS+CSS,
                    injects window.HOOKSGRAPH_JSON_URL / HOOKSGRAPH_DEMO_URL inline
                    before the bundle, marks the script tag (and its inline bootstrap)
                    as type="module".
hooks.json          Ships empty (0 bytes, committed). Replace via
                    `hooksgraph parse <dir> -o packages/theme/hooks.json`.
                    Empty body → viewer catches the JSON.parse error and renders its
                    empty state (upload / demo prompt).
demo.json           Optional, gitignored. Drop a parsed graph here to enable the
                    viewer's "Load demo" button. functions.php exposes the URL via
                    window.HOOKSGRAPH_DEMO_URL; absent → global set to null so the
                    viewer skips its HEAD probe entirely and hides the button.
assets/             Generated by scripts/build-theme.js (viewer dist + manifest.json).
                    Gitignored.
favicon.png / favicon.svg / og-image.png / screenshot.png   Theme-owned static files.
                    Mirrors the viewer's index.html metadata so the WP-rendered <head>
                    matches the standalone viewer.
```

## Commands

Run from the **monorepo root** (workspace-aware).

| Command                                  | Description                                                                  |
| ---------------------------------------- | ---------------------------------------------------------------------------- |
| `pnpm build:theme`                       | Builds the viewer and copies `dist/` → `assets/`; writes `assets/manifest.json` |
| `pnpm -F @hooksgraph/viewer dev`         | Dev the viewer standalone (the theme has no dev mode of its own)             |

## How it wires up

- `scripts/build-theme.js` runs the viewer build, copies hashed `dist/assets/*` into `packages/theme/assets/`, and parses `dist/index.html` for the entry `<script type="module" src>` and `<link rel="stylesheet" href>` — strips the dist-relative `assets/` prefix, writes them to `assets/manifest.json` so `functions.php` enqueues hashed filenames without runtime HTML parsing.
- `functions.php` reads that manifest, enqueues the bundle (deferred, in footer), then `wp_add_inline_script(… , 'before')` injects two globals consumed by `useGraphData.js`:
  - `window.HOOKSGRAPH_JSON_URL` → always set to `<theme>/hooks.json`.
  - `window.HOOKSGRAPH_DEMO_URL` → set to `<theme>/demo.json` **only when the file exists**; otherwise emitted as literal `null`.
- The viewer's `resolveDataUrls()` is tri-state on demo: key absent (CLI/server flow) → default `./demo.json`; explicit `null` (this theme path) → skip probe + hide button; non-empty string → use as URL.

## Gotchas

- **Bundle is an ES module.** `wp_script_attributes` / `wp_inline_script_attributes` filters force `type="module"` on the `hooksgraph-viewer-js` and `hooksgraph-viewer-js-before` IDs. Don't change the asset handle without updating those ID checks.
- **`manifest.json` paths are bare filenames** (e.g. `index-XXX.js`) — `scripts/build-theme.js` strips the `assets/` prefix before writing because files sit at `assets/` root, not `assets/assets/`. If you change the copy destination, re-check the strip.
- **`hooks.json` ships empty (0 bytes) and is committed.** That's intentional — replacing it locally is the documented user flow. Don't auto-populate it from CI or the empty-state UX breaks.
- **`demo.json` is gitignored.** Detection is `file_exists()` at request time. If you cache the manifest or theme metadata, don't cache the demo presence.
- **Favicon block is suppressed when WP has a Customizer Site Icon** (`has_site_icon()`). WP renders its own `<link rel="icon">` via `wp_site_icon()` and emitting another would duplicate.
- **Fallback template (`index.php`) is intentional.** This theme renders meaningfully only on the front page. Don't add the WP template hierarchy — `single`, `archive`, `404` all funnel to the fallback by design.
- **No PHP business logic.** Don't add admin pages, options, REST endpoints, or anything stateful here — that belongs in [`packages/plugin/`](../plugin/). The theme is a host shim; keep it that way.
